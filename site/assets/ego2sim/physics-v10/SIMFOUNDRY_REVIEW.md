## 代码实际做了什么

- `simfoundry/utils/processing_utils.py:758–802`：按 `depth * K^-1 [u,v,1]` 反投影，然后应用矩阵。参数名 `world_to_cam_tf` 容易误读，代码实际直接乘入；集成时应按公式和往返测试核对，不能只看名字。
- `scripts/pipeline/A_reconstruction/stages/4_unify_world_frame.py:74–125`：深度范围裁剪、半径去噪、桌面法向构造 Z-up；相机到世界矩阵明确采用 `R @ T(-origin)`，不是把相机原点平移直接写成世界平移。最终旋转输出重新读取 raw 点云，不能把这个输出自动称为已经去噪的点云。
- `scripts/pipeline/A_reconstruction/stages/8_match_object_poses.py:227–278, 430–496`：对分割对象点云做有限性/点数检查；OBB 对角线粗定尺度，多随机 SO(3) 初值的 CPD，含可变尺度拟合，再用距离排名。498 行后的额外 scale grid 循环被注释；不能凭日志声称它已执行完整尺度网格搜索。透明玻璃的单目深度依然不能作为真实表面。
- `scripts/pipeline/A_reconstruction/stages/11_make_objects_sim_ready.py:193–244`：VLM 根据对象图像、尺寸、体积估计 mass/friction，调用碰撞分解导入。它们是估计值，不能替代称重、摩擦与胶头压力标定。
- `scripts/pipeline/A_reconstruction/stages/12_stabilize_physics.py:44–112, 330–360`：整理场景时会清零速度，并临时固定已摆放物体，再清零多次。适合生成初始布局，不能借用来证明本任务的自由释放后自然稳定。
- `simfoundry/utils/data_gen_utils.py:129–191`：对象局部关键点，经对象世界位姿，再经机器人世界位姿逆矩阵映射。适合减少桌面布局改变时直接复制世界轨迹的问题。
- `scripts/pipeline/C_application/stages/5_generate_demos.py:563–577, 1209–1235`：可选 physical/assisted grasp，未指定时设 assisted；运动规划携带对象默认 scale=0.8。对我们不能使用辅助焊接来替代抓持，也不能缩小实际滴管碰撞几何来获得通过。
- `simfoundry/utils/ground_plane_utils.py` 与 `AGENTS.md` 的 scene contract：显示背景不是碰撞桌面；场景读入与验证应使用相同支持面、质量、关节限位。场景 JSON 写了参数不等于引擎实际加载了参数。

## 本轮实际新增

1. 原始 `5 mm` 管尖相对位移成为必过门槛，同时保留接触处累计滑移、胶头中心和转角等检查，所有门槛求 AND。增加“汇总声称成功但原始门槛失败”的拒绝测试。
2. 全原生步按阶段定位管尖峰值；近邻真实 30 Hz 状态把偏移精确拆成胶头中心平移与长杆转动项，记录采样差异及输入哈希，不用几何动画冒充物理解。
3. `check_pipeline_contract.py` 对真实上游位姿做 SE(3)、坐标往返、XYZW→WXYZ 四元数转换检查；拒绝转置、毫米误当米、左右手坐标反射三类错误。
4. 对引擎实际加载的质量、惯量、摩擦、几何、关节、驱动限制与已发布基线逐项核对；质量再与 XML 作者值独立核对，记录支持面重力与物体自由度。
5. 对对象局部抓点改动做 FK 反算：事件管尖目标不变，插值最大变化0.070 mm，避免通过改任务目标获得成功。
6. 保留三维人手候选的失败清单，绝不把几何近邻当作已测接触力；渲染继续逐项绑定实际物理与液体记录。
